`account` reports what happened against what was expected. It sits **at the floor** (`intention: state`): it serves by recording honest variance, it does not try to move the reader. Use [`template.md`](template.md) to write one.

- **Generative verb:** *report against.*
- **Stake:** honest variance. An account is only worth reading if it compares what happened to what was expected; a list of activities with no baseline is not an account.
- **Move structure:** restate the baseline / expectation → state what actually occurred → name the variance and its causes → state the consequence or next step.
- **Failure mode:** narrating activity instead of reporting against an expectation — the perennial "status-green" report.
- **Genres:** status report, postmortem, changelog entry, retrospective.

Recipient note: a postmortem drifts toward `explain` — when its centre of gravity is the *why* of a failure, write it under the variant verb *diagnose*. An `account` is often **diachronic** (a frozen entry in a stream, like a `CHANGELOG`). See [`../../../patterns.md`](../../../patterns.md).
