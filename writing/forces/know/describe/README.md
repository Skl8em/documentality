`describe` states the facts exhaustively and neutrally. It sits **at the floor** (`intention: state`): it serves the reader who needs to *find* a fact and trust the statement is complete within its scope; it does not aim to move them. Use [`template.md`](template.md) to write one.

- **Generative verb:** *specify.*
- **Stake:** completeness and neutrality. The reader must be able to find any fact and trust the statement is exhaustive within its declared scope.
- **Move structure:** delimit the scope → state the facts in a stable, predictable order → exemplify where a fact is ambiguous → mark the bounds of what is *not* covered.
- **Failure mode:** narrativizing. The moment a reference explains *why*, it has drifted to `explain`.
- **Organize by the subject**, not the reader: a stable, predictable order the reader can navigate by structure, because success is correctness, not a changed reader.
- **Genres:** reference manual, API documentation, data dictionary, glossary, specification.

Recipient note: a `describe` is read out of order and looked up under pressure; keep chunks self-sufficient (`reader: M` benefits most). See [`../../../patterns.md`](../../../patterns.md).
